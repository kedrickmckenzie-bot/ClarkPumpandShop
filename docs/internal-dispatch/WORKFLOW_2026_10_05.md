## What changed

- Review opens the shared All open list for facilities and field managers. The row shows active Tasks with the person, title and due time. Review routing reuses existing work-order, assignment, hold and cancellation commands; metadata and the route share one transaction. Store-manager intake creates an attributed review assessment, with deterministic ordering when the initial report and review share a timestamp.
- Job preparation stores optional human estimates, technician instructions and confirmation timing on the canonical work order. Updating an active plan creates an immutable schedule revision. Remaining-time edits require an active visit. There are no inferred or default durations.
- Plan supports seven days, this/next week, grouped incoming work, alphabetical people, factual skill/region matches, known hours and unknown counts. Drag or quick actions move jobs; up/down changes stop order. Undo submits a new version-checked change. Appointment time and original due dates are preserved; late moves require an explicit keep action.
- Today uses scoped actual visits and append-only technician status. Active visits win over optional status. Blocked or held work cannot appear as the next ready stop. The client refreshes its data without routing away or closing a job panel.
- Checkout presents six outcomes with notes, existing file evidence and the working-when-left check. The optional next screen supports heading to a planned job, getting parts, a break, a different job, or done. Status history is not a break-duration report.
- A Fixed result schedules the existing confirmation task for the selected delay. Confirmation cannot be submitted before it opens. Overdue confirmation gets a reminder before escalation. A negative answer uses the existing same-work-order reopening command. Without required store confirmation, a manager must still close with a reason.
- Manager landing counts link to their supporting Review/Dispatch queries. Owners and read-only roles receive no planning mutations. All tenant-owned commands and query additions preserve organization/store boundaries.
